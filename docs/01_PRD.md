# PRD — 상상우리 LiteLLM 비용 거버넌스 PoC

## 1. 제품명

**상상우리 LiteLLM AI 비용 거버넌스 PoC**

## 2. 배경

상상우리 AI 에이전트 프로젝트에서는 직원들이 다양한 유료 LLM을 사용할 가능성이 있다. 특히 Claude Code, Codex CLI, Gemini CLI, Hermes Agent 같은 도구는 단순 챗봇보다 토큰 사용량이 크고 장시간 자동 실행될 수 있다.

따라서 기업 예산 범위 안에서 다음을 통제해야 한다.

- 누가 사용했는가
- 어떤 도구로 사용했는가
- 어떤 모델을 사용했는가
- 얼마를 썼는가
- 예산 초과 시 실제로 차단되는가
- 고가 모델 접근을 제한할 수 있는가

본 PoC는 Google Chat 같은 최종 사용자 채널을 붙이기 전에, **LiteLLM이 비용 통제 관문으로 실사용 가능한지**를 먼저 검증한다.

---

## 3. 문제 정의

### 현재 문제

1. 직원이 각자 API Key 또는 개인 구독으로 AI를 쓰면 비용 추적이 어렵다.
2. 개발용 AI 에이전트는 반복 호출로 비용이 급증할 수 있다.
3. 고가 모델 사용을 조직적으로 제한하기 어렵다.
4. 개인/팀/도구별 ROI 산정이 어렵다.
5. 관리자 입장에서 예산 초과 전 경고·차단 체계가 없다.

### 해결 가설

LiteLLM Proxy를 중앙 게이트웨이로 두고, 직원/도구별 Virtual Key를 발급하면 다음이 가능하다.

- API 호출을 회사 관문으로 집중
- 가상키별 모델 권한 제한
- 가상키별 예산/속도 제한
- 사용량 로그 기반 비용 추적
- 직원/도구/모델별 리포트

## 4. PoC 목표

### Primary Goal

**LiteLLM으로 직원별·도구별 유료 LLM 사용을 예산 범위 안에서 실제 차단/추적할 수 있음을 증명한다.**

### Secondary Goals

- Claude Code 등 코딩 에이전트 연동 전제 검증
- 관리자가 이해할 수 있는 비용 리포트 산출
- 운영 도입 전 리스크 목록 도출
- 상상우리 AI 에이전트 프로젝트의 비용 거버넌스 기반 확보

## 6. 핵심 기능 요구사항

### F1. LiteLLM Proxy 실행

- LiteLLM Proxy가 로컬/VPS에서 실행되어야 한다.
- PostgreSQL, Redis와 연결 가능해야 한다.
- `/health`, `/models` 호출이 가능해야 한다.

### F2. 마스터키/가상키 분리

- 관리자는 `LITELLM_MASTER_KEY`만 사용한다.
- 직원/도구는 Virtual Key만 사용한다.
- 마스터키는 절대 클라이언트에 노출하지 않는다.

### F3. 직원·도구별 가상키 생성

- `dev-kim-claude`
- `dev-kim-codex`
- `dev-kim-gemini`
- `staff-lee-chat`
- `admin-park-test`

각 키는 다음 메타데이터를 가져야 한다.

- key_alias
- user_id
- team_id
- tool
- allowed_models
- max_budget
- budget_duration
- rpm_limit
- tpm_limit

### F4. 모델 접근 제한

- 일반 직원 키는 저가 모델만 허용한다.
- 개발자 키는 도구별 모델 그룹만 허용한다.
- 허용되지 않은 모델 호출은 실패해야 한다.

### F5. 예산 제한

- 가상키별 월 예산을 설정한다.
- 테스트용으로 낮은 예산을 설정해 초과 차단을 검증한다.
- 예산 초과 후 추가 호출은 실패해야 한다.

### F6. 사용량 추적

최소 다음 기준으로 리포트가 가능해야 한다.

- 사용자별
- 도구별
- 모델별
- 가상키별
- 기간별

### F7. 데모 호출 스크립트

- 정상 호출 스크립트
- 비허용 모델 호출 스크립트
- 예산 초과 호출 스크립트
- 사용량 리포트 export 스크립트

### F8. 관리자 리포트

Markdown 또는 HTML로 다음을 보여준다.

| 항목 | 설명 |
|---|---|
| 총 호출 수 | 전체 호출 횟수 |
| 총 비용 | 추정 또는 실제 비용 |
| 사용자별 비용 | kim/lee/park 등 |
| 도구별 비용 | claude/codex/gemini/chat |
| 차단 이벤트 | 예산 초과/모델 제한 |
| 남은 예산 | 가상키별 잔액 |

### F9. PoC용 사용자/관리자 UI

PoC에는 최소 2개 화면을 포함한다.

| 화면 | 목적 | 필수 기능 |
|---|---|---|
| 사용자 테스트 UI | 직원이 Gateway 경유 LLM 호출을 체험 | user/tool/model/task/prompt 선택, 응답/비용/차단사유 표시 |
| 관리자 통제 UI | 비용 통제 가능성 확인 | 가상키 현황, 예산/잔액, 사용자·도구·모델별 사용량, 차단 이벤트, 리포트 export |

구체 화면 구성과 Charly 테스트 절차는 `08_UI_AND_TEST_SCENARIOS.md`를 따른다.

## 10. 데모 스토리

1. 관리자가 직원/도구별 가상키를 발급한다.
2. 김 개발자가 Claude Code용 키로 허용 모델을 호출한다.
3. 김 개발자가 허용되지 않은 고가 모델을 호출하면 차단된다.
4. 이 직원이 낮은 예산을 초과하면 호출이 차단된다.
5. 관리자가 리포트를 열어 누가, 어떤 도구로, 어떤 모델을 썼는지 확인한다.
6. 결론: LiteLLM 기반 비용 통제는 기술적으로 가능하다.

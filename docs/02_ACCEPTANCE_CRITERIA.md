# Acceptance Criteria — LiteLLM 비용 거버넌스 PoC

## 1. Gate 1 — 실행 환경

- [ ] `README.md`의 명령만으로 개발 환경을 준비할 수 있다.
- [ ] `.env.example`이 필요한 환경변수를 모두 설명한다.
- [ ] LiteLLM Proxy가 실행된다.
- [ ] PostgreSQL/Redis가 실행되거나, fallback/mock 모드가 명확히 표시된다.
- [ ] `curl /health` 또는 동등한 명령으로 상태 확인이 가능하다.

## 2. Gate 2 — 가상키 정책

- [ ] Master Key와 Virtual Key가 분리되어 있다.
- [ ] 직원/도구별 키 alias가 생성된다.
- [ ] 키별로 `models`, `max_budget`, `budget_duration`, `rpm_limit`, `tpm_limit`가 설정된다.
- [ ] 생성된 실제 키 원문은 문서에 저장하지 않는다.
- [ ] redacted key 정보만 저장한다.

## 3. Gate 3 — 모델 접근 제한

- [ ] 허용 모델 호출은 성공한다.
- [ ] 허용되지 않은 모델 호출은 실패한다.
- [ ] 실패 사유가 로그 또는 응답에서 확인된다.
- [ ] 일반 직원 키와 개발자 키의 허용 모델이 다르다.

## 4. Gate 4 — 예산 초과 차단

- [ ] 낮은 예산의 테스트 키를 만들 수 있다.
- [ ] 반복 호출 또는 mock cost injection으로 예산 초과 상태를 만들 수 있다.
- [ ] 예산 초과 후 추가 호출은 실패한다.
- [ ] 실패 응답/로그가 `docs/VERIFICATION_REPORT.md`에 기록된다.

## 5. Gate 5 — 사용량 리포트

- [ ] 사용자별 사용량이 구분된다.
- [ ] 도구별 사용량이 구분된다.
- [ ] 모델별 사용량이 구분된다.
- [ ] 차단 이벤트가 기록된다.
- [ ] Markdown 리포트를 생성할 수 있다.

## 6. Gate 6 — 테스트

- [ ] `uv run pytest`가 통과한다.
- [ ] 예산 정책 테스트가 있다.
- [ ] 모델 권한 정책 테스트가 있다.
- [ ] 리포트 파싱 테스트가 있다.
- [ ] 외부 API Key가 없을 때도 최소 정책 테스트는 통과한다.

## 7. Gate 7 — 데모 가능성

- [ ] 5분 이내에 데모 흐름을 설명하고 실행할 수 있다.
- [ ] 정상 호출과 차단 호출을 모두 보여줄 수 있다.
- [ ] 관리자 리포트를 보여줄 수 있다.
- [ ] 미검증/제외 범위를 명확히 말할 수 있다.

## 최종 성공 판정

아래 3개가 모두 되면 PoC의 핵심 성공으로 본다.

1. **가상키별 모델 제한 성공**
2. **가상키별 예산 초과 차단 성공**
3. **사용량이 직원·도구·모델 단위로 구분되어 리포트됨**

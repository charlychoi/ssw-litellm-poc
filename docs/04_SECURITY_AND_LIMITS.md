# Security and Limits — LiteLLM 비용 거버넌스 PoC

## 1. 보안 원칙

### 마스터키 보호

- `LITELLM_MASTER_KEY`는 관리자 서버에서만 사용한다.
- 직원 PC, Claude Code 설정, Codex config, Gemini CLI 환경변수에는 절대 넣지 않는다.
- 직원과 도구에는 Virtual Key만 전달한다.

### 가상키 저장

- `.env`는 git에 포함하지 않는다.
- 문서에는 전체 키를 저장하지 않는다.
- 리포트에는 앞 8자/뒤 4자 정도만 redaction한다.

예:

```text
sk-abc12345...wxyz
```

### 로그 주의

- 요청/응답 원문 로그에는 개인정보나 고객정보가 포함될 수 있다.
- PoC에서는 민감 데이터 입력 금지.
- 운영에서는 PII masking 또는 body logging off 정책 필요.

---

## 2. LiteLLM 버전 리스크

LiteLLM v1.82.7 / v1.82.8은 공급망 공격 이슈가 보고된 버전이므로 사용 금지하고, `litellm[proxy]>=1.83.10,<2.0.0` 범위로 고정한다.

PoC 구현자는 다음을 해야 한다.

- 안전 버전으로 pinning
- 설치 버전 기록
- `docs/VERIFICATION_REPORT.md`에 `litellm --version` 또는 package version 기록

---

## 3. 통제 가능한 범위

LiteLLM으로 통제 가능한 것은 **회사 가상키를 사용하는 API 기반 호출**이다.

| 대상 | 통제 가능 여부 |
|---|---:|
| Google Chat 봇 백엔드 | 가능 |
| Claude Code API 호출 | 가능, 실제 설정 검증 필요 |
| Codex CLI API 호출 | 가능, 실제 설정 검증 필요 |
| Gemini CLI API 호출 | 가능, 실제 설정 검증 필요 |
| Hermes Agent provider 호출 | 가능 |
| 사내 FastAPI/자동화 앱 | 가능 |

---

## 4. 통제 불가능하거나 제한적인 범위

| 대상 | 이유 |
|---|---|
| ChatGPT 일반 데스크탑 앱 | 개인 계정/구독 로그인 기반 |
| Claude 일반 채팅 앱 | 개인 Pro/Max 로그인 기반 |
| Gemini 웹앱 | Google 계정 기반 |
| 직원 개인 API Key | 회사 Gateway 밖 호출 |
| 브라우저에서 직접 쓰는 외부 AI 서비스 | 회사 API 관문 미경유 |

정책 문구 권장:

> 업무용 유료 LLM 사용은 회사가 승인한 AI Gateway 경로를 통해서만 수행한다. 개인 구독 또는 개인 API Key로 처리한 업무는 회사 예산·ROI 측정 대상에 포함하지 않는다.

---

## 5. 운영 도입 전 추가 필요사항

| 영역 | 필요 조치 |
|---|---|
| 인증 | 직원 SSO/Google Workspace 연동 |
| 권한 | 직무/부서/프로젝트별 모델 권한 |
| 키 관리 | 발급, 회수, 로테이션, 폐기 기록 |
| 로그 | 보존 기간, 접근 권한, 감사 로그 |
| 개인정보 | PII masking, body logging 정책 |
| 장애 대응 | LiteLLM/DB/Redis 백업 및 복구 |
| 비용 관리 | 월 예산, 증액 승인, 알림 |
| 교육 | 개인 구독 우회 금지 안내 |

---

## 6. PoC에서 의도적으로 단순화한 것

- 실제 직원 개인정보 없음
- 실제 결재 승인 없음
- 실제 SSO 없음
- Google Chat 없음
- HA/백업 없음
- 완성형 대시보드 없음
- 실제 원가 정산은 provider별 가격과 차이가 있을 수 있음

---

## 7. PoC 실패로 봐야 하는 경우

아래 중 하나라도 안 되면 LiteLLM 비용 통제 PoC는 실패 또는 재설계가 필요하다.

1. Virtual Key별 모델 제한이 작동하지 않음
2. 예산 초과 후에도 계속 호출 가능
3. 사용량 로그에서 키/사용자/모델 구분 불가
4. 마스터키 없이는 호출이 불가능한 구조
5. 설정 재현이 불가능함

---

## 8. 운영 성공 조건

기술 검증 후 실제 운영 성공 조건은 다음이다.

- 직원은 회사 가상키 경로만 사용한다.
- 고가 모델은 승인된 사용자만 접근한다.
- 예산 초과 시 자동 차단 또는 저가 모델 전환이 된다.
- 관리자는 주간 리포트로 비용과 ROI를 본다.
- 퇴사/이동/프로젝트 종료 시 키가 즉시 회수된다.
